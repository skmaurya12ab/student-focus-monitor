# Offline Machine Learning Model Baseline & Evaluation (Phase 13)

> **Phase 13 Status**: Implemented & Verified.  
> **Absolute Phase Boundary Notice**: Phase 13 implements **only** offline ML model training, preprocessing pipeline construction, evaluation, threshold tuning, and model artifact creation. It does **not** integrate ML into the live detector, replace the rule-based detector, alter detector thresholds or rules, modify WebSocket detection behavior, add runtime ML predictions, introduce shadow mode, or alter live focus state transitions. Shadow-mode runtime integration belongs strictly to **Phase 14**.

---

## 1. Executive Objective

The core objective of Phase 13 is to answer:
> *"Can a supervised machine learning baseline learn distraction and focus patterns from physical movement telemetry alone, evaluated without user or session leakage?"*

Phase 13 establishes the project's first scientifically defensible supervised ML baseline using the columnar dataset artifacts exported by Phase 12 (`dataset_v1`).

---

## 2. Training Data Source & Provenance

The model trainer consumes versioned Parquet dataset artifacts generated by Phase 12:
- Path: `data/datasets/phase12/dataset_v1/dataset.parquet`
- Reproducibility Manifest: `data/datasets/phase12/dataset_v1/manifest.json`
- Feature Schema: `data/datasets/phase12/dataset_v1/schema.json`
- Split Summary: `data/datasets/phase12/dataset_v1/split_summary.json`

The training pipeline does **not** issue direct queries to the live PostgreSQL database during model training, ensuring deterministic reproducibility.

---

## 3. Primary & Secondary Targets

### Primary Target: `label_distracted`
- **Semantics**:
  - `1`: Distracted
  - `0`: Focused
  - `null`: Unknown / Calibration (strictly excluded from training and evaluation)
- **Filtering Policy**:
  - Calibration samples (`is_calibration == True`) are excluded.
  - Rows marked invalid or excluded by Phase 12 validation (`is_excluded == True`) are excluded.
  - Rows with missing/null target are excluded.

### Secondary Targets (Extensible Multi-Label Architecture)
The pipeline is designed to support category-specific binary targets:
- `label_looking_away`
- `label_phone_use`
- `label_yawning`
- `label_drowsy`
- `label_leaning_back`
- `label_away_from_desk`

---

## 4. Model Input Features (Strict Allowlist)

The model is strictly restricted to the 38 `MODEL_FEATURE_COLUMNS` defined in `ml.dataset.config`:
1. **Core Numerical (7)**: `head_pitch`, `head_yaw`, `head_roll`, `ear`, `mar`, `min_hand_cheek_distance`, `shoulder_z`
2. **Core Presence (3)**: `face_present`, `pose_present`, `hand_count`
3. **Baseline Deltas & Motion Rates (15)**: `head_pitch_from_baseline`, `head_yaw_from_baseline`, `head_roll_from_baseline`, `left_ear`, `right_ear`, `left_hand_cheek_distance`, `right_hand_cheek_distance`, `shoulder_z_delta`, `torso_aspect_ratio`, `torso_posture_delta`, `head_yaw_rate`, `head_pitch_rate`, `head_roll_rate`, `shoulder_z_rate`, `hand_cheek_distance_rate`
4. **Baseline Calibration Medians (5)**: `baseline_head_yaw`, `baseline_head_pitch`, `baseline_head_roll`, `baseline_shoulder_z`, `baseline_torso_aspect_ratio`
5. **Missing Value Indicators (8)**: `head_pitch_missing`, `head_yaw_missing`, `head_roll_missing`, `ear_missing`, `mar_missing`, `min_hand_cheek_distance_missing`, `shoulder_z_missing`, `torso_aspect_ratio_missing`

### Excluded from Model Inputs (Zero Leakage)
The feature matrix strictly **bars**:
- Rule detector outputs (`rule_*`)
- Tracker states and persistence timers (`tracker_*`)
- Discrete detection event timing (`DetectionEvent`)
- Human feedback metadata (`session_feedback`)
- Target columns (`label_*`, `focus_state_label`)
- Provenance columns (`sample_id`, `session_hash`, `user_id`, timestamps)
- Post-session aggregate analytics

Any attempt to pass forbidden columns immediately triggers `FeatureLeakageError`.

## 5. Model Architecture & Preprocessing Pipeline

### Primary Baseline: Logistic Regression
- **Algorithm**: `LogisticRegression(solver='lbfgs', max_iter=1000, random_state=42)`
- **Pipeline Architecture**:
  ```text
  Raw Input DataFrame
         ↓
  verify_feature_matrix (38 allowlisted MODEL_FEATURE_COLUMNS only)
         ↓
  SimpleImputer(strategy='median')  <-- Fit strictly on training split
         ↓
  StandardScaler()                  <-- Fit strictly on training split
         ↓
  LogisticRegression()              <-- Fit strictly on training split
         ↓
  Calibrated Class Probabilities & Predictions
  ```

### Challenger Model: Random Forest
- **Algorithm**: `RandomForestClassifier(n_estimators=100, max_depth=6, random_state=42)`
- Evaluated optionally to test whether non-linear interactions materially improve upon the linear baseline.

### Preprocessing Leakage Prevention
Preprocessing statistics (median for imputation, mean and standard deviation for scaling) are learned **strictly from the training partition**. Validation and test partitions are transformed using the fitted training pipeline without recalculating statistics.

---

## 6. Grouped User Splitting & Leakage Prevention

The model training pipeline respects the authoritative Phase 12 grouped user split:
- **Grouping Hierarchy**: `User -> Study Session -> Telemetry Sample`
- **Integrity Guarantee**:
  - All sessions for a user reside entirely within one split (`train`, `val`, or `test`).
  - No user appears in both `train` and `test`.
  - No session appears in both `train` and `test`.
  - No telemetry row appears across splits.

---

## 7. Data Readiness Gate & Real-Data Gating

The pipeline classifies the dataset state into one of three explicit readiness levels:
- **State A**: `READY FOR ML TRAINING` (Multi-user real dataset with sufficient class balance).
- **State B**: `PIPELINE READY BUT INSUFFICIENT REAL DATA` (Valid pipeline, but single-user or single-class data prevents multi-user evaluation).
- **State C**: `DATA INVALID / PIPELINE BROKEN` (Corrupt artifact or missing columns).

### Current Repository Audit Status: State B
- The local database currently contains 2,012 raw telemetry samples across 14 study sessions and 3 users.
- 361 samples are calibration samples. All samples for User 2 (36 samples) and User 3 (49 samples) are calibration samples.
- User 1 has 1,651 exported non-calibration samples (7 sessions).
- Under grouped user splitting, unseen-user generalization requires at least 3 distinct users with valid non-calibration telemetry. Because only 1 user currently has non-calibration data, train has 0 samples and test has 1,596 eligible samples.
- The pipeline correctly reports:
  `Status: B. PIPELINE READY BUT INSUFFICIENT REAL DATA`
  `evaluation_not_valid: True`
  `validity_reason: "Training split contains 0 samples; insufficient distinct users for multi-split generalization."`
- **Zero Fabrication**: No fake labels, SMOTE oversampling, or synthetic rows are used to fabricate real performance metrics.

## 8. Evaluation Metrics & Threshold Policy

### Metrics Catalog
- **Primary**: Precision, Recall, F1 Score
- **Secondary**: Accuracy, ROC-AUC (when both classes present), PR-AUC (Average Precision)
- **Confusion Matrix**: `[[TN, FP], [FN, TP]]`
- **Class Accounting**: Positive count, negative count, positive rate per partition

### Threshold Policy
- Default classification threshold: **0.50**.
- Optional threshold tuning: Evaluates candidate thresholds in `[0.10, 0.90]` strictly on the **validation partition** optimizing F1 score. Test set labels are **never** used for threshold selection.

---

## 9. Rule-Based Detector Baseline Comparison

When evaluation splits contain both classes, the offline pipeline compares the ML model against the existing heuristic rule detector:
- The composite rule indicator (`any_rule_distracted`) is evaluated against the same human-supported target.
- Metrics are contrasted side-by-side: `ML F1 vs Rule F1 (delta_f1)`.
- **Note**: The rule detector is an offline benchmark, **not** absolute ground truth.

---

## 10. Model Interpretability

Diagnostic feature ranking is automatically extracted:
- **Logistic Regression**: Coefficients sorted by absolute magnitude, direction (`positive` = indicates distraction, `negative` = indicates focus), and intercept.
- **Random Forest**: Gini feature importances sorted descending.
- **Caution**: Coefficients and importances represent statistical correlations within the training sample and do not imply causal mechanisms.

---

## 11. Model Artifacts & Privacy Guarantee

Model bundles are written to `ml/models/phase13/distracted/`:
1. `model.joblib`: Serialized scikit-learn pipeline (ignored by Git via `.gitignore`).
2. `metadata.json`: Model version, dataset version, hyperparameters, anonymized counts, software versions.
3. `evaluation.json`: Experiment manifest with data validity and model validity flags, metrics, interpretability, and rule comparison.
4. `feature_schema.json`: Catalog of the 38 allowable feature names and types.

### Privacy Assurance
- Zero raw `user_id`, email addresses, or Google subject IDs appear in artifacts.
- Zero image, video, audio, or camera frame buffers appear in artifacts.
- Model binary files (`*.joblib`, `*.pkl`) are explicitly ignored by Git.

---

## 12. CLI Usage

The training pipeline is executed via `ml.models.phase13.cli`:

```bash
# Baseline Logistic Regression on default Phase 12 dataset
python -m ml.models.phase13.cli \
  --dataset data/datasets/phase12/dataset_v1 \
  --target label_distracted \
  --output ml/models/phase13/distracted \
  --model logistic \
  --seed 42

# Optional Random Forest Challenger
python -m ml.models.phase13.cli \
  --dataset data/datasets/phase12/dataset_v1 \
  --target label_distracted \
  --output ml/models/phase13/distracted_rf \
  --model random_forest \
  --seed 42
```
